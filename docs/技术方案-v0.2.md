## 1. 产品定义与设计原则

**一句话**：五笔 86 与拼音免切换混打、按住即说的离线语音、可插拔的本地 AI 辅助——并且随使用自动贴合主人习惯的输入法。

五条原则（按优先级）：

1. **离线优先**：打字、语音、AI 默认全离线；联网是显式 opt-in，不偷跑。
2. **自适应**：越用越贴手——词频、自动造词、语音热词、候选排序、调参建议都从使用中来。
3. **不阻塞**：任何增强（AI、统计、同步）不得拖慢「按键 → 上屏」主链路；AI 超时即弃。
4. **隐私默认**：数据全留本机，可导出、可一键清空；音频不落盘。
5. **可分享**：代码合规（GPLv3）、安装门槛低、文档够朋友自助上手。

## 3. 核心输入设计：五笔 86 + 拼音混合

### 3.1 混合策略（体验目标：不用切换、不用想当前是什么模式）

基于 librime schema DSL（YAML），复用官方 `rime-wubi`（86）+ `rime-pinyin-simp` 已验证的混合配方：

1. 默认按五笔编码解析（4 码上限，形码优先）；
2. 同一编码流并行挂拼音 translator，拼音候选排在五笔候选之后；
3. 纯长串且无五笔命中 → 自动前移拼音候选（`recognizer` pattern + `initial_quality` 分流）；
4. 拼音反查保留（打拼音看五笔编码提示，辅助学五笔）。

### 3.2 上屏行为默认值（M1 手感调校时可调，见 §9 待讨论）

| 行为 | 默认建议 | 说明 |
|---|---|---|
| 四码自动上屏 | 开 | 五笔核心效率项 |
| 空码顶字上屏 | 待讨论 | 误触率 vs 效率 |
| 候选个数 | 6–8 | 可配 |
| 简拼 | 不主动启用（五笔为主） | 拼音侧允许全拼+简拼混输 |

> schema 具体参数在 M1 落地时以实测手感为准，全部参数化热调，不写死在代码里。

### 3.3 词库

- 五笔：`rime-wubi` 86 词库为底；拼音：`rime-pinyin-simp`（或 rime-ice）为底；
- **用户词典开 `enable_user_dict: true`** —— 这是「自适应」的第一级（详见 §4）；
- 自定义短语文件：日期、邮箱、常用句（静态快捷输入，与学习无关）。

## 4. 自适应学习子系统（核心差异化）

> 需求原文：「这是一个不断使用中贴合用户习惯的输入法」。设计为三级递进，逐级可关。

### 4.1 L1 · 词频与自动造词（随用随学，默认开）

- 依托 librime userdb：每次上屏更新词频权重、自动组词（打过的词组下次直接成词）；
- 迁移友好：userdb 文件独立，换机/重装随数据目录带走。

### 4.2 L2 · 习惯画像（统计驱动，默认开，只统计不外传）

本地统计（滚动窗口，数据留在本机）：

| 统计项 | 用途 |
|---|---|
| 简拼/全拼使用率、模糊音误用率 | 生成「启用简拼/模糊音」调参建议 |
| 候选翻页深度、选重率 | 候选排序与候选数调参建议 |
| 高频字词 Top-N、四码直达率 | 五笔词库增补候选 |
| 错字回改率（上屏后立即删改） | 反馈进词频与 AI correct 场景 |

产出：设置页一张「习惯报告」+ 一键应用的调参建议（**只建议不自动改**，防止学歪了难回滚）。

### 4.3 L3 · 个人语料与热词（可选开，默认关）

- 上屏文本本地留存（显式 opt-in）→ 两个用途：
  1. **语音热词自动更新**：从语料抽取高频专名（人名/项目名/术语）→ `hotwords.txt` → ASR 识别率提升；
  2. **AI 个性化语料**：本地 GGUF 后端的 few-shot 示例 / 重排特征来源（未来可做 LoRA 微调，未排期）。
- 隐私红线：留存语料**永不上传**；设置页一键导出/清空；不进 iCloud。

### 4.4 数据边界（所有级别的统一约束）

- 全本地存储于数据目录；统计与语料分文件，粒度独立开关；
- 一键「学习数据重置」：清 userdb + 画像 + 语料，回到出厂手感。

## 5. 语音输入设计（按住指定键）

### 5.1 交互状态机

```
idle ──按下热键──▶ listening（实时滚动显示转写）──松开──▶ transcribing
                                                              │
   Esc 取消 ◀────────────────────────────────────────────────  ▼
                                                        标点+热词后处理
                                                              │
                                              上屏（或低置信度→提示重说）
```

- 按住期间候选区实时滚动 partial 结果（流式 ASR）；
- **Esc 取消**、松手即上屏；后处理（标点、热词）在松手后 <500ms 内完成；
- 音频不落盘：VAD 内存环形缓冲，转写完即弃。

### 5.2 热键（按住指定键）

| 项 | 设计 | 备注 |
|---|---|---|
| 默认键位 | 待讨论（§9）：macOS 候选「右 ⌘」单修饰键；备选组合键 | 单修饰键体验最好但有被 app 吞的风险 |
| 可配置 | 设置页改键，支持单修饰键与组合键两类 | 两平台同一配置 schema |
| 实现要点 | macOS：IMK `NSEventTypeFlagsChanged` 监听修饰键按下/抬起；Windows：TSF 键事件 + 低级键盘钩子兜底 | 单修饰键在部分 app（游戏/远程桌面）可能失效 → 组合键兜底必留 |

### 5.3 识别管线（全离线）

```
麦克风采集 → Silero VAD → SenseVoiceSmall (int8, 流式) → CT-Transformer 标点
            → 热词表后处理 → 上屏
```

- 模型懒加载（首次使用 / 开机后第一次按热键时加载，常驻内存 ~百 MB 级）；
- 热词表：`hotwords.txt` 人工可编辑 + L3 自动更新（§4.3）；
- 失败兜底：超时/低置信 → 提示重说，不瞎猜上屏；
- macOS 特有：麦克风 **TCC 权限**（`NSMicrophoneUsageDescription` 必配），权限弹窗归属输入法 app。

## 6. AI 辅助设计（默认本地）

### 6.1 SPI 契约（本期钉死，实现后置）

```cpp
struct Candidate { std::string text; double score; std::string source; };
struct AiContext { std::string before_cursor; std::string schema_id; bool from_voice; };

class IAiAssistProvider {
public:
  virtual std::vector<Candidate> rescore(const std::vector<Candidate>&,
                                         const AiContext&) = 0;   // 候选重排
  virtual std::vector<std::string> complete(const std::string& prefix,
                                            const AiContext&) = 0; // 续写/联想
  virtual std::string correct(const std::string& text,
                              const AiContext&) = 0;              // 纠错润色
  virtual bool healthy() = 0;
};
```

### 6.2 后端优先级（已拍板：本地默认）

| 优先级 | 后端 | 说明 |
|---|---|---|
| ① 默认 | **本地 GGUF（llama.cpp）** | 小模型（≤2GB，中文能力优先，如 Qwen 小参数量档），CPU 可跑 |
| ② 可选 | OpenAI 兼容 HTTP | base_url + api_key + model 三元组配置，接任意兼容服务 |
| ③ 实验 | Apple 端侧模型 | macOS 设备端零延迟，目标系统上实测可用性后定 |

### 6.3 场景落地顺序

1. **语音同音字纠错**（`correct`）——语音转写错字是最高频痛点，收益最直接；
2. **候选重排**（`rescore`）——打字时异步重排下一页候选；
3. **续写联想**（`complete`）——短语级补全。

### 6.4 工程约束

- 全部异步，默认超时 800ms，超时即弃，**绝不阻塞上屏**；
- AI 总开关 + 三个场景独立开关，默认全关（用户开了才跑）；
- 传给后端的上下文默认只有当前句（本地后端不受限）；
- 调用审计日志（只记字段不记全文，可关）；
- 模型文件独立目录、手动放入或首次使用时提示下载，不打进 app bundle。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| **GPLv3 传染（分发给朋友即触发）** | 高 | 分发二进制须整个衍生项目 GPLv3 开源 → 策略：**定稿即建公开仓**（个人项目无秘密，最省事）；词库配方各 LICENSE 分发前过目；私有配置/语料数据不进仓 |
| macOS 签名/公证（朋友安装体验） | 高 | 未签名输入法在他人机器上被 Gatekeeper 拦 → 预算 Apple Developer 账号（$99/年）走正式签名+公证；过渡期文档写明「右键打开」手动放行 |
| IMK/TSF 兼容坑（Secure Input、终端、游戏） | 高 | 不自研壳，站 Squirrel/Weasel 上游坑位；兼容问题先查上游 issue |
| 按住单修饰键被个别 app 吞 | 中 | 热键可配置 + 组合键兜底必留；默认键位 §9 定稿后真机验证 |
| ASR 模型体积/内存 | 低 | int8 量化 + 懒加载；模型不进 bundle |
| AI 隐私 | 中 | 默认本地、默认关闭、最小上下文、审计日志 |
| 自学习「学歪」 | 中 | 只建议不自动改（L2）；一键学习数据重置；userdb 可回滚备份 |
| 上游停更 | 低 | fork 后自主可控 |

## 9. 本轮待讨论清单（定稿即开发）

1. **语音热键默认键位**：「右 ⌘」单修饰键 vs 组合键（如 `⌃⇧Space` 按住）？我倾向单修饰键为主、组合键兜底，但需要真机验证常用 app 的表现。
2. **上屏行为**：四码自动上屏开不开（我建议开）；空码顶字要不要。
3. **学习数据默认开关**：L1 词频默认开我建议没问题；L2 画像默认开/关？L3 语料留存维持默认关？
4. **候选框外观**：M1 直接用 Squirrel 原版外观，还是第一版就要自绘皮肤？
5. **产品显示名**：仓库叫 `mine-input`，菜单栏/候选框上显示什么名字（中文名？）。
6. **AI 本地模型取舍**：≤2GB 小模型做纠错/重排预期够用（我的判断：够）；你若要「续写出整句」级别体验，模型与内存预算要重新谈。
