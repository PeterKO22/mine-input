## 1. 产品定义与设计原则（修订）

**一句话**：一套五笔 86 + 拼音混合、按住即说的输入法，跑在你所有设备上；背后是你自己的 AI——懂你的上下文，像动态提词器一样跟着你的语音走；习惯数据全端同步，隐私不出你自己的地盘。

六条原则（按优先级）：

1. **一套习惯，全端一致**：词频、造词、热词、调参画像在所有设备是同一份数据，自动同步。
2. **自己的 AI**：后端永远是「你的」——自托管 Hub（本地/远程服务器）或端侧模型；不出售、不经过第三方云。
3. **上下文感知**：理解你正在做什么（屏幕、语音、输入历史），建议才有价值——但采集分级、逐项可控（§8.1）。
4. **不阻塞**：按键→上屏永不等待 AI/同步/采集；建议永远是异步旁路。
5. **隐私默认**：数据要么留端、要么进你自己的 Hub；传输加密；可导出、可一键清空。
6. **可分享**：朋友能装、能懂（知情同意清单 + 自建 Hub 指南）；代码 GPLv3 合规。

## 2. 平台能力矩阵（诚实版硬墙）

| 能力 | macOS | Windows | Android | iOS |
|---|---|---|---|---|
| 自定义输入法框架 | ✅ InputMethodKit | ✅ TSF | ✅ InputMethodService | ⚠️ Keyboard Extension（能力受限） |
| 五笔+拼音混合（librime） | ✅ | ✅ | ✅（librime 有 Android 移植先例） | ⚠️ 同左，需实测性能 |
| 语音输入（按住即说） | ✅ | ✅ | ✅（RECORD_AUDIO 正常） | ❌→⚠️ **键盘扩展麦克风受系统限制**（详见下注） |
| 屏幕上下文采集 | ✅ ScreenCaptureKit + Vision OCR | ✅ Graphics Capture + OCR | ⚠️ 无障碍服务读屏文本（侧载可行，商店受限）/ MediaProjection（逐次授权） | ❌ **系统硬墙**：键盘扩展无法截屏；仅能拿输入框前后文（`documentContext`） |
| 环境音频采集 | ✅（系统环回+麦克风） | ✅（WASAPI loopback） | ⚠️ 仅建议「输入时采集」 | ❌ 后台环境音无合规路径 |
| 本地小模型 AI | ✅ | ✅ | ✅（llm.llama/llama.cpp Android 可跑小模型） | ⚠️ Core ML 小模型（实测） |
| 连接 Hub 拿建议 | ✅ | ✅ | ✅ | ✅（键盘扩展可开网络[Full Access]） |
| 分发路径 | 自签/公证 | 安装包 | 侧载 APK（商店大概率拒审） | TestFlight/自签（商店对键盘权限极严） |

**iOS 键盘麦克风的说明**：键盘扩展对麦克风的访问是系统级受限的（业内通行做法是「跳转宿主 App 完成听写」；个别厂商键盘的实现机制不透明）。**设计按「不可用」兜底**：iOS 语音输入走「一键跳转宿主 App 听写 → 返回上屏」流程，另列真机调研任务（§13-T1），验证通过再开增强路径。iOS 定位因此是 **Tier C 伴侣版**：打字 + AI 建议 + 同步齐全，语音体验折损可接受/可等待实证。

## 3. 总体架构（v0.3：客户端 + 自托管中枢）

```
        ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
        │  macOS   │ │ Windows  │ │ Android  │ │   iOS    │
        │ Tier A   │ │ Tier A   │ │ Tier B   │ │ Tier C   │
        └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘
             │  同一客户端内核（C++/Rust 薄移植层，平台壳薄）        │
             │  ┌────────────────────────────────────┐          │
             │  │ 输入引擎 librime(混合schema) 语音 sherpa-onnx │  │
             │  │ 自适应学习 L1-L3   上下文引擎 C0-C2          │  │
             │  │ AiAssist SPI（本地/远程同契约）              │  │
             │  └────────────────────────────────────┘          │
             │                    │                              │
             │   同步协议(增量, E2E可选) + 建议流(WS/HTTP)         │
             └────────────────────┼──────────────────────────────┘
                                  ▼
                 ┌────────────────────────────────────┐
                 │   AI Hub（自托管，你的地盘你做主）      │
                 │  部署形态：①家中常驻设备/NAS（默认）    │
                 │           ②自有远程服务器             │
                 │           ③混合：端侧小模型兜底        │
                 │  职责：                                 │
                 │  · 模型托管（LLM：重排/纠错/续写/提词）  │
                 │  · 数据同步中枢（词典/画像/热词/日志）   │
                 │  · 交互日志归集与理解（跨端上下文拼图）   │
                 │  · 多用户隔离（朋友各自的数据分区）      │
                 └────────────────────────────────────┘
```

关键决策：**AiAssist SPI 的契约同时是本地调用接口和远程协议**——端侧后端与 Hub 后端实现同一组方法，换后端不改调用方。这就是「本地 AI 或远程 AI 随便选」的工程表达。

## 4. 核心输入设计（沿用 v0.2 §3，不变项摘要）

- 五笔 86 + 拼音混合：librime schema `ping_wubi_mixed`，形码优先、拼音并联、免切换（细节见 v0.2 §3）；
- 上屏行为默认值：四码自动上屏（开）、空码顶字（待讨论）、候选 6–8；
- 词库：rime-wubi 86 + pinyin-simp 为底；用户词典常开（= L1 自学习）；
- 移动端同 schema 同词库，候选框 UI 换平台原生控件。

## 5. 自适应学习子系统（升级：跨端生效）

三级结构沿用 v0.2 §4（L1 词频/造词、L2 习惯画像、L3 个人语料/热词），v0.3 的变化是**数据归属与同步**：

| 层 | 数据 | 生效范围 | 同步 |
|---|---|---|---|
| L1 | 用户词典 userdb（词频、自动造词） | 全端 | RIME 自带 userdb 同步机制 + Hub 中转（§9） |
| L2 | 习惯画像（简拼率/翻页/回改率 → 调参建议） | 全端合并计算 | 增量计数器上行，画像 Hub 合成后下行 |
| L3 | 个人语料 + 语音热词 + 高频专名 | 全端共享 | 语料归集 Hub（加密），热词文件同步 |
| C | 交互日志（§8.2） | 主要供 Hub 理解 | 增量上行，保留策略可配 |

新增原则：**「学习在哪端发生不重要，成果全端共享」**——在手机上学的词，电脑上立刻能用（最终一致，分钟级）。

## 6. 语音输入（按住指定键）——全端差异

交互状态机（idle → 按住 listening[实时滚动] → 松开 transcribing → 标点+热词 → 上屏；Esc 取消）全端一致。差异只在采集入口：

| 端 | 采集 | 备注 |
|---|---|---|
| macOS / Windows | 应用内 PTT 热键（可配置） | 管线：VAD → SenseVoiceSmall → 标点 → 热词 |
| Android | 键盘上 PTT 按键（长按说话） | 同上，模型 int8 常驻可选 |
| iOS | **跳转宿主 App 听写 → 返回上屏**（兜底路径） | 系统限制；若 T1 实证可行再改在键盘内听写 |

热词表（含 L3 自动更新的专名）**全端同步**——这就是「语音习惯同一套」的落点。

## 7. AI Hub 与 SPI（背后是你自己的 AI）

### 7.1 三种部署形态（用户任选，随时切换）

| 形态 | 描述 | 适用 |
|---|---|---|
| **本地 Hub（默认）** | 家中 Mac mini / NAS / 一台常驻设备跑模型 + 同步服务；设备在家网或经 Tailscale/自建 VPN 回连 | 「本地 AI + 自动同步」原话 |
| **远程 Hub** | 自有 VPS/服务器，模型跑在上面，设备公网 HTTPS 回连 | 出门在外也要完整智能 |
| **混合** | 端侧小模型兜底（断网可用基础建议），联网时 Hub 增强 | 推荐常态配置 |

### 7.2 SPI v2 契约（本地调用 = 远程协议，同一组方法）

```cpp
struct Candidate { std::string text; double score; std::string source; };
struct AiContext { std::string before_cursor; std::string app_id;
                   bool from_voice; std::string context_digest; };

class IAiAssistProvider {
public:
  // —— 打字/选词场景（v0.2 已有）——
  virtual std::vector<Candidate> rescore(const std::vector<Candidate>&, const AiContext&) = 0;
  virtual std::vector<std::string> complete(const std::string& prefix, const AiContext&) = 0;
  virtual std::string correct(const std::string& text, const AiContext&) = 0;
  // —— v0.3 新增：提词器 & 学习回路 ——
  virtual void suggest(const AiContext&, SuggestionStream& out) = 0;  // 流式建议（动态提词）
  virtual void ingest(const InteractionEvent&) = 0;                    // 交互事件上行（供理解）
  virtual bool healthy() = 0;
};
```

- 远程实现 = 同一契约走 HTTPS/WebSocket（`suggest` 走流式通道）；本地实现 = 进程内调用；
- **断网降级**：Hub 不可达 → 端侧小模型接管基础功能，日志排队，联网补传；
- 隐私约束：`context_digest` 只传摘要化上下文（§8.2 的窗口拼图），传输 TLS，可选 E2E（Hub 端也看不到明文的模式，代价是 Hub 侧模型无法利用全局日志——做成开关）。

### 7.3 模型

- Hub 侧：一个中文友好的开源 LLM（7B 级量化起步，视 Hub 硬件），统一服务四个场景；
- 端侧兜底：≤2GB GGUF 小模型（重排/纠错够用，v0.2 §6 结论沿用）；
- 模型与提示词模板版本化，随同步通道下发（换模型全端同时生效）。

## 8. 上下文引擎与动态提词器（v0.3 核心新增）

### 8.1 采集分级（逐项开关，默认档待讨论 §13）

| 级别 | 采集内容 | 触发 | 平台 |
|---|---|---|---|
| **C0 基础** | 输入框前后文、当前应用名、最近输入历史、（可选）剪贴板 | 每次按键会话 | 全端 |
| **C1 屏幕+环境音** | 屏幕快照→OCR 文本、系统音频环回→ASR 转写 | **按下键盘时触发**（防抖 1–2s，N4 原文行为） | macOS/Windows |
| **C2 移动增强** | 无障碍服务读屏文本 / MediaProjection（逐次授权） | 同上 | Android（侧载） |

- iOS 只有 C0（输入框上下文）——硬墙，不硬凑；
- 所有采集**分级独立开关**，设置页明示「正在采集什么」；
- 频控：同一应用内防抖、敏感应用黑名单（密码框自动暂停——librime/TSF/IMK 有安全输入模式信号可利用）。

### 8.2 交互日志（「记录我的交互过程」）

时间索引事件流，本地优先、增量上行 Hub：

```
InteractionEvent := { ts, device_id, app_id,
                      kind: key_session|voice_session|candidate_pick|suggestion_feedback,
                      text_in, text_out, ocr_digest?, asr_digest?,
                      keystroke_cadence, suggestion_shown, suggestion_taken }
```

- **本地**：SQLite，设置页可查/可导出/可一键清空；保留策略可配（默认 30 天滚动）；
- **Hub 侧**：跨端归集 → 组装「上下文窗口」（最近 N 分钟的屏幕文本 + 音频转写 + 输入史），供 `suggest` 使用，也是「理解用户」的长期记忆；
- **明线**：这是键盘 + 录屏级数据。产品上必须给使用者（包括朋友）**逐项知情同意**，并支持每用户独立加密分区（§10）。

### 8.3 动态提词器（N5 的交互设计）

三种唤起：

1. **随打即出**：常规输入时异步补一列「智能候选」（不占默认候选位，单独一组）；
2. **快捷键唤起**：按 `⌥Esc`（暂定，可配）→ 光标旁弹提词面板，基于当前上下文流式生成；
3. **语音实时提词**：语音输入进行中，面板随转写文本**实时刷新后续建议**——说话讲到一半，下一句的提词跟着变（这就是「动态提词器」的核心体验）。

实现要点：`suggest` 流式接口 + 本地防抖；语音场景下每 300–500ms 增量调用（转写 delta 触发），UI 只渲染最新一版。全程**不上屏、不抢焦点**，Tab/数字键才采纳。

## 9. 数据同步子系统

- **通道**：设备 ↔ Hub 直连（HTTPS + token 设备注册），内网直连或 Tailscale/自建 VPN；可选「E2E 加密模式」；
- **数据面**：L1 userdb（RIME 原生同步格式）、L2 增量计数器、L3 热词/语料、C 交互日志、AI 配置与提示词模板、schema 版本；
- **合并策略**：userdb 用 RIME 自带合并（时间戳取新）；L2 计数器增量相加；冲突自动、极少人工干预；
- **一致性**：最终一致，分钟级；同步失败静默排队，不弹窗骚扰；
- **朋友场景**：Hub 多用户分区，每用户独立密钥，互不可见。

## 10. 隐私与安全（红线设计）

1. **数据不出地盘**：默认全部数据只存在于「你的设备 + 你的 Hub」；不经过任何第三方云（模型全部开源/自托管）；
2. **传输**：TLS 必开；可选 E2E（Hub 零知识模式）；
3. **静态加密**：交互日志与语料在端和 Hub 均落盘加密；
4. **知情同意**：首次开启 C1/C2 采集时逐项弹明示（「将记录屏幕文本与音频转写，仅存于你的设备/Hub」）；朋友版本必须走同一清单——**这类权限没有「默认全开」的正当性**；
5. **安全输入模式**：密码框、支付场景自动暂停采集（利用系统 Secure Input 信号）；
6. **一键熔断**：全局「停止一切采集」开关，物理可见状态（菜单栏/状态条图标变色）；
7. **合规提示（写进用户文档）**：录制屏幕/音频的合法性依属地法律而定；本设计仅支持「本人设备、本人数据」，不提供也不支持监控他人。
